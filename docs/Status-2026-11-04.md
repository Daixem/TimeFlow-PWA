## Veröffentlichung: was automatisch läuft und was noch getrennt ist

Ein Push auf `main` startet die GitHub-Pages-Veröffentlichung der statischen
PWA. Die Connect-Anmeldung, API und Sites-Datenbank werden dadurch nicht
aktualisiert. Daher ist noch nicht erreicht, dass ein einziger Git-Push sowohl
die App-Oberfläche als auch den produktiven Server ändert.

Die PWA kann auf Geräten App-Dateien automatisch nachladen. Das ist keine
Bestätigung, dass Serverfunktionen oder Kontodaten ebenfalls aktualisiert oder
auf allen Geräten abgeglichen wurden.

## Nächste Schritte

1. Einen vollständigen und geschützten Exportweg für die aktive Connect-Datenbank ermöglichen. Ein solcher Weg ist derzeit nicht in der Sites-Verwaltung vorhanden.
2. Den Export in eine getrennte Wiederherstellungsdatenbank laden und Schema, Tabellen, Zeilenzahlen sowie Stichproben vergleichen.
3. Erst mit geprüftem Backup und Restore den produktiven Server, die Anmeldung und Kontozuordnung in die Zielarchitektur überführen.
4. Den offiziellen Veröffentlichungsablauf so verbinden, dass `main` sowohl PWA als auch Server aktualisiert, ohne private Nutzerdaten oder Geheimnisse in GitHub abzulegen.
5. Danach auf mehreren Geräten mit demselben Konto die Dienstpläne, Teamdaten, Konfliktbehandlung, Push und automatische Updates prüfen.
6. Erst nach bestandenen Daten- und Zugriffsprüfungen den alten Beta-/Connect-Weg aus dem Nutzerablauf entfernen.

## Grenzen dieses Prüfstands

Der Datenbanküberblick hat keine persönlichen Zeileninhalte ausgegeben. Ein
vollständiger Export, eine produktive Wiederherstellung, eine Anmeldung mit
E-Mail-Code/Google und ein produktiver Cloudflare-Worker wurden nicht
nachgewiesen. Es wurden keine produktiven Daten geändert und keine Tests oder
Geräteabnahmen ausgeführt.
